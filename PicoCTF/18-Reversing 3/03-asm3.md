## Descripcion
What does asm3(0xccf13937,0xbf0a24e4,0xf44d6917) return? Submit the flag as a hexadecimal value (starting with '0x'). NOTE: Your submission for this question will NOT be in the normal flag format. [Source](https://challenge-files.picoctf.net/c_fickle_tempest/248b3201b28c4b333623337ef57b478c151690b62e8ce62acc07e19ec6cab02b/test.S)
## Solucion
descargamos el archivo del reto y revisamos el contenido:
```
┌──(min㉿WIN-U49VUBQG3G3)-[~]
└─$ cat test.S.2
asm3:
        <+0>:   endbr32
        <+4>:   push   ebp
        <+5>:   mov    ebp,esp
        <+7>:   xor    eax,eax
        <+9>:   mov    ah,BYTE PTR [ebp+0x9]
        <+12>:  shl    ax,0x10
        <+16>:  sub    al,BYTE PTR [ebp+0xd]
        <+19>:  add    ah,BYTE PTR [ebp+0xf]
        <+22>:  xor    ax,WORD PTR [ebp+0x12]
        <+26>:  nop
        <+27>:  pop    ebp
        <+28>:  ret
```
En este reto tenemos tres argumentos de entrada de 32 bits que se acomodan en la pila de acuerdo al prólogo de la función:

ebp+0x8 = Arg 1 = 0xccf13937    
ebp+0xc = Arg 2 = 0xbf0a24e4
ebp+0x10 = Arg 3 = 0xf44d6917

Como las instrucciones van a extraer pedazos especificos usando offsets en memoria, mapeamos el valor byte por byte en Little Endian:
- **Arg 1 (`[ebp+0x8]`)**: `[ebp+0x8]` = `0x37`, `[ebp+0x9]` = `0x39`, `[ebp+0xa]` = `0xf1`, `[ebp+0xb]` = `0xcc`

- **Arg 2 (`[ebp+0xc]`)**: `[ebp+0xc]` = `0xe4`, `[ebp+0xd]` = `0x24`, `[ebp+0xe]` = `0x0a`, `[ebp+0xf]` = `0xbf`

- **Arg 3 (`[ebp+0x10]`)**: `[ebp+0x10]` = `0x17`, `[ebp+0x11]` = `0x69`, `[ebp+0x12]` = `0x4d`, `[ebp+0x13]` = `0xf4`

ahora en la linea +7 tenemos:
```
<+7>:   xor    eax,eax
```

Limpia por completo el registro eax dejándolo en 0x00000000 entonces sus subregistros ax, ah y al también valen 0
vamos a la linea +9:
```
<+9>:   mov    ah,BYTE PTR [ebp+0x9]
```
Mueve el byte ubicado en (ebp+0x9) (que mapeamos como 0x39) al registro ah (la parte alta de ax), Ahora ax vale 0x3900
en la línea +12:
```
<+12>:  shl    ax,0x10
```
aqui se desplaza el registro ax a la izquierda por 0x10 bits como el registro ax es de solo 16 bits, al desplazarlo 16 posiciones todo su contenido se desborda y el registro se llena por completo de ceros entonces ax vuelve a valer 0x0000 (por lo tanto ah = 0x00 y al = 0x00)
nos pasamos a la línea +16:
```
<+16>:  sub    al,BYTE PTR [ebp+0xd]
```
Resta el byte en (ebp+0xd) (0x24) al registro al (0x00). La operación en 8 bits es 0x00 - 0x24, lo que nos da como resultado 0xdc. Ahora ax vale 0x00dc
En la línea +19:
```
<+19>:  add    ah,BYTE PTR [ebp+0xf]
```
se suma el byte en (ebp+0xf) (0xbf) al registro `ah` (`0x00`). La operación es `0x00 + 0xbf = 0xbf`. Ahora el registro `ax` vale `0xbfdc`.

En la línea +22:
```
<+22>:  xor    ax,WORD PTR [ebp+0x12]
```
se hace una operación XOR entre nuestro ax = 0xbfdc y el WORD que empieza en la dirección (ebp+0x12), mirando el mapa del tercer argumento, los bytes en (ebp+0x12) y (ebp+0x13) forman el valor 0xf44d

hacemos la operación XOR bit a bit:
```
- 0xbfdc -> 1011 1111 1101 1100
- 0xf44d -> 1111 0100 0100 1101
- XOR -> 0100 1011 1001 0001 que se traduce a 0x4b91
```
El registro ax termina con el valor 0x4b91
Al final tenemos esto:
```
<+26>:  nop
<+27>:  pop    ebp
<+28>:  ret
```
El programa no hace nada en el nop, limpia el stack frame y retorna lo que quedó en eax. Como los 16 bits superiores de eax nunca se volvieron a tocar desde el xor inicial, el valor de retorno final es lo que se quedó en ax, es decir, 0x4b91, siendo esta nuestra bandera.
